Why · 为什么需要它

周报不缺信息，缺的是「被梳理过的信息」

三名成员各写一段文字，管理者要在几百字里拼出项目全貌：谁在推进、谁被卡住、风险在哪、还缺什么信息。 这个过程重复、耗时，而且高度依赖个人经验。助手把这一步固化成一条可复用的工作流。

🧩

信息分散，口径不一

每个人的周报结构不同：有人写百分比，有人写「已联调」，有人只写「进行中」。汇总时无法横向对比。

助手统一拆成 任务 · 状态 · 负责人 · 描述 四要素，状态受限于「已完成 / 进行中 / 未开始 / 阻塞」。
⏱️

风险总是滞后暴露

「等接口文档」「等设计稿」「环境不够」这类描述常被当作普通进展一笔带过，等到影响上线才被重视。

独立的风险评估节点给出 等级 🔴🟡🟢 · 影响 · 原因 · 应对建议 · 优先级，并强制排序。
📝

向上汇报要重新写一遍

读完之后，管理者还要自己组织语言写周报给上级，格式每次都不一样，容易漏项。

按固定模板自动生成 Markdown 周报，并一键转成 Word 文档，格式稳定、条目齐全。

Capabilities · 核心能力

五项能力，对应工作流中的五段职责

不是把「写周报」交给大模型，而是把一段分析流程拆成职责单一、可复核的节点，每一步都有明确的输入与结构化输出。

01

周报归一化

输入 1–3 名成员的姓名与周报正文，代码节点把自由文本整理成结构化的成员列表，避免在提示词里做脆弱的字符串拼接。

代码节点 · Python多成员
02

任务拆解与状态判定

把每份周报拆成独立任务，标注负责人与状态；状态被约束在固定的四个枚举值内，便于统计与横向比较。

JSON Schema枚举约束
03

风险识别与分级

只基于已识别的风险做评级、原因与应对分析，禁止凭空创造新风险，输出按优先级排序的风险清单。

三级风险优先级排序
04

信息完整度体检

检查是否缺少负责人、截止时间、风险原因、下一步计划，给出 0–100 的完整度评分，并生成要向成员追问的问题清单。

评分 0–100追问清单
05

管理报告自动成稿

按固定模板渲染正式的周报文档，包含进展分表、风险表、下一步计划与待确认事项，并直接转换为 Word 文件交付。

Implementation · 工程实现

让大模型「可交付」的四个关键设计

以下片段均取自项目 DSL 的真实配置，可在页面底部下载完整文件核对。

●项目状态分析 · 结构化输出定义Dify Workflow · v0.7.0

    


    

      

        
① 用 Schema 锁住输出形状

        
三个分析节点全部开启结构化输出。任务状态被限定在四个枚举值内，风险必须携带影响，评分是数字——下游模板可以直接取字段，不需要再做文本解析，也不会因为措辞变化导致流程崩溃。

      

      

        
② 用提示词约束职责边界

        
风险评估节点被明确要求「只分析 risks 字段，不得依据 tasks 或 summary 创造新风险」，并保留原始风险描述；无法判断原因时统一填「需要进一步确认」，把不确定性显式暴露出来而不是编造。

      

      

        
③ 并行分支减少重复计算

        
风险评级与完整度检查互不依赖，因此并列在同一层并行执行，共同复用项目状态分析的结果，最后汇聚到模板节点。既缩短链路耗时，也让每个节点职责单一、便于单独调优。

      

      

        
④ 交付物闭环到 Word

        
最终节点不是返回一段文字，而是调用文档转换插件生成 Word 文件并作为文件数组输出。管理者拿到的是可以直接转发给上级的文档，而不是需要再排版一遍的聊天记录。

📄 交付物一：正式周报

        
项目进展（已完成 / 进行中 / 阻塞三张表）、风险与问题、下一步计划、信息完整度与待确认事项。Markdown 成稿后转为 Word 文档。

      

      

        
🧩 交付物二：结构化数据

        
任务数组、原始风险、风险评级、完整度评分与追问清单均有独立字段，可直接被其他系统消费，用于看板、周会材料或历史趋势统计。

      

      

        
🎯 交付物三：信息体检结论

        
这一项常被忽略：它把「周报写得够不够好」变成可量化的分数与具体问题，让管理动作从「催周报」变成「追问要点」。

这条流水线还能长出什么

      
当前版本已跑通「输入 → 分析 → 成稿 → 交付」全链路，后续可以按同样的节点思路继续扩展。

    


    

      

        
接入知识库：让分析带上历史上下文

        
将历史周报与项目文档存入知识库，分析时可检索「上周说本周要完成的任务是否完成」，把单周期快照变成跨周趋势判断。

        RAG 检索节点
